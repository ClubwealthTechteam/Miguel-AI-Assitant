# Summary {data-eyebrow="Section 1"}

This plan moves the Club Wealth phone numbers from TurboDial 1 (TD1) to TurboDial 2 (TD2).

- On November 25, the Project Head sets up all RM and Events users and numbers in TD2.
- On November 30, the RMs and the Events team get training and start a 3-day beta-live.
- During the beta-live, the team finds the TD1 features that the RMs need and that TD2 does not have.
- On December 3, TD2 becomes the only system for the RMs and the Events team.

# Phases 4 and 5: Beta-live and full go-live (Nov 30–Dec 3) {data-eyebrow="Section 7"}

### Purpose of the beta-live

The RMs use TD2 for their real work for 3 days. The team records each TD1 feature that an RM needs and cannot find in TD2.

### The feature gap log

On November 25, make a shared sheet with these columns:

| Column | Content |
|---|---|
| Date | The date of the gap. |
| User | The RM or Events user. |
| TD1 feature | The feature that the user used in TD1. |
| What happened in TD2 | What the user tried in TD2, and the result. |
| Impact | **Blocks work**, **Slows work** or **Nice to have**. |
| Workaround | A different way to do the task in TD2, if one exists. |
| Action and owner | The fix, the person who does it, and the date. |

### TD1 features to check during the beta-live

Each RM does a check of these TD1 features in TD2. Record the result in the feature gap log.

1. A call rings the RM and then goes to the office cell after 2 or 3 rings.
2. The office cell hears "Press 1 to answer" before the call connects.
3. A voicemail goes to the RM by email, with a transcript.
4. A screen shows the Keap contact when a call comes in.
5. A call outcome puts a tag on the Keap contact.
6. A recorded message drops on a voicemail with one click.
7. A call goes to a queue, for example "Parked Calls".
8. The owner gets a copy of each text.
9. One call rings more than one person at the same time.
10. The labels and status tags of the numbers show, for example "WARMING" and "RESTING".
11. The RM sees the call history and the texts of a contact on one screen.
12. The RM calls from Keap with one click.

### Daily steps (Nov 30, Dec 1 and Dec 2)

1. At 8:30 AM, do the daily check in Section 14.
2. During the day, each user records each gap in the feature gap log immediately.
3. At 4:00 PM, the Project Head meets the RMs for 15 minutes.
4. In the meeting, review each new gap and its impact.
5. Fix each gap that a TD2 setting can fix on the same day.
6. Keep all other gaps in the log. Do not send them to TurboDial support during the beta-live.

::: warning
**Warning:** If a gap blocks the work of an RM, do the undo procedure (Section 12) for that RM's numbers. The RM uses TD1 until the gap has a fix or a workaround.
:::

### Feature gap review (Wednesday, December 2, 3:00 PM)

The Project Head, the Principal, the backups and the RMs attend.

1. Review each gap in the feature gap log.
2. Give each gap one action:
   - **Fix in TD2:** the Project Head changes a TD2 setting.
   - **Vendor item:** the gap needs TurboDial support.
   - **Workaround:** add the workaround to the TD2 SOP: Agent Guide.
   - **Accept:** the team does not need the feature.
3. Give each action an owner and a date.
4. Do the go/no-go check (Section 10) for the full go-live.

### Send the RM concerns to TurboDial support (Wednesday, December 2, 5:00 PM)

1. Collect all "Vendor item" gaps from the feature gap log.
2. Put them in one email to TurboDial support.
3. For each gap, write the TD1 feature, what happened in TD2 and the impact.
4. Put the "Blocks work" gaps first.
5. Ask TurboDial support for a meeting in the week of December 7.
6. Record the answer and the date of each fix in the feature gap log.

The full go-live starts only if:

- each gap with the impact "Blocks work" has a fix or a workaround;
- the Principal approves "Go".

### Full go-live (Thursday, December 3)

1. At 7:00 AM, turn on the TD2 switches again for each RM who went back to TD1 during the beta-live.
2. Do the 5 tests (Section 11) on these numbers.
3. At 7:30 AM, send the full go-live message (Section 13).

# Procedure for one number {data-eyebrow="Section 9"}

1. Make sure that the inbound call route for the number is ready.
2. Go to Settings › TurboDial › Phone Numbers.
3. Find the number. Press Ctrl+F and type the last 4 digits.
4. Click the pencil on the row of the number.
5. Type the **Name** from the number list.
6. Set the **Owner** and **Forward SMS To** to the TD2 user of the person in the number list.
7. Set the **Inbound Call Route**.
8. Set **Public for Caller ID** and **Record inbound calls** from the number list.
9. Turn on "Use TurboDial 2.0 Voice".
10. Turn on "Use TurboDial 2.0 SMS".
11. Click **Apply**.
12. In the number list, record the date and your initials in "Number added".

::: warning
**Warning:** Do not click "Release Number". This action removes the number from the account permanently. Do not click "Add Phone Number". This action buys a new number.
:::

# Undo procedure {data-eyebrow="Section 12"}

### When to start the undo procedure

- A call to a moved number does not ring a person.
- A call or text from TD2 shows an incorrect number, and you cannot correct it in 15 minutes.
- A text to a moved number does not arrive in TD2 in 15 minutes.

### Procedure

1. Change the inbound call route of the number. Send all calls to the office cell, (206) 300-1000.
2. Open the number in Settings › TurboDial › Phone Numbers.
3. Turn off "Use TurboDial 2.0 Voice".
4. Turn off "Use TurboDial 2.0 SMS".
5. Click **Apply**. The calls and texts go back to TD1.
6. Call the number from the test phone. Make sure that TD1 rings.
7. Record the number, the problem and the time in the number list.
8. Tell TurboDial support.
9. Stop the go-live for that group until the cause is known.

::: tip
**Note:** Do steps 1 to 5 in less than 5 minutes.
:::
